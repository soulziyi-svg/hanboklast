[이번 과제의 구현 범위]
이 프로젝트는 학습용 한복 판매 쇼핑몰 데모 사이트이다.
실제 PG 결제와 실제 택배사 배송 API는 이번 구현 범위에서 제외한다.
단, 다음 기능은 Supabase를 실제 데이터 저장소로 사용하여 구현한다.
회원가입 / 로그인: Supabase Auth
사용자 프로필: Supabase Database
상품 정보: Supabase Database
상품 이미지: 프로젝트 로컬 이미지 또는 Supabase Storage
카테고리 및 컬렉션: Supabase Database
장바구니: 로그인 사용자는 Supabase Database를 기본으로 사용
주문 정보: Supabase Database
주문 상세 상품: Supabase Database
상품 사이즈 및 재고: Supabase Database
후기: Supabase Database
후기 이미지: Supabase Storage
관리자 상품 등록 / 수정 / 삭제: Supabase Database와 연동
관리자 사이트 설정: Supabase Database와 연동
상담 신청: Supabase Database
배송 상태: Supabase Database의 mock 배송 상태를 사용
실제 결제 PG API와 실제 택배사 API는 연결하지 않는다.
결제 버튼을 누르면 학습용 가상 결제 완료 처리를 하고 주문 정보를 Supabase에 저장한다.
GPT 챗봇의 OpenAI API Key는 클라이언트 코드에 직접 작성하지 않는다.
GitHub Pages에서 Secret Key를 사용할 수 없으므로 GPT 연동이 필요한 경우 서버 또는 Supabase Edge Function을 통한 API Proxy 구조를 사용한다.
서버 API가 구성되지 않은 개발 환경에서는 mock chatbot 모드를 사용할 수 있게 한다.
Supabase 연결 정보 중 브라우저에서 사용 가능한 Publishable Key만 클라이언트에서 사용하고, Secret Key 또는 service_role 권한 키는 프론트엔드 코드나 GitHub Pages에 절대 포함하지 않는다.
Supabase의 공개 스키마에 있는 테이블에는 RLS(Row Level Security)를 적용하고 사용자의 권한에 따라 조회/등록/수정/삭제 범위를 제한한다.

작업 규칙:
1. 각 이미지의 파일명을 확인한다.
2. 이미지와 관련된 섹션을 정확히 연결한다.
3. 잘못된 상대 경로와 절대 경로를 수정한다.
4. 모든 img 태그에 구체적인 alt 텍스트를 작성한다.
5. 이미지 비율이 찌그러지거나 여백이 생기지 않도록 object-fit: contain을 적용한다.
6. 데스크톱과 모바일에서 이미지가 잘리지 않도록 반응형 처리한다.
7. 존재하지 않는 이미지 파일은 임의로 만들거나 대체하지 않는다.
8. 변경 후 개발 서버를 실행해서 이미지가 정상적으로 나타나는지 확인한다.
9. 이미지가 깨지면 경로와 파일명의 대소문자를 다시 확인한다.
10, 이미지는 원본 비율을 그대로 유지하고, 확대창 안에서 전체 이미지가 모두 보이게 해줘. 이미지의 가로와 세로 중 더 긴 쪽을 확대창 크기에 맞추고, 남는 공간은 여백으로 처리해줘.
확대 이미지의 크기는 다음 기준으로 적용해줘.
이미지 너비: 최대 100%
이미지 높이: 최대 90vh
이미지 비율: 원본 비율 유지
이미지 맞춤 방식: contain
이미지 중앙 정렬
이미지 확대 또는 축소 과정에서 찌그러짐과 잘림이 없어야 함
이미지 바깥쪽 여백은 투명한 배경으로 표시
세로로 긴 이미지와 가로로 긴 이미지 모두 전체가 보이게 함
닫기 버튼은 이미지와 겹치지 않게 화면 오른쪽 위에 배치

#컨텐츠1

중앙포지션 "한국의 아름다움을 나만의 굿즈로 맞춤제작" / Yeongwol 폰트는 영월체 사용해 / 60px /진한 그레이(#6E6E6E)

### 한복 상품 카드형 무한 자동 띠배너
한복 상품을 보여주는 **가로형 무한 자동 슬라이드 띠배너**를 구현한다.

#### 기본 구조
- 상품 카드 크기: 300px × 600px  / 이미지 크기 : 300px * 450px
- 여러 개의 상품 카드가 가로 한 줄로 연결되는 구조
- 카드 사이 간격: 0px
- 카드가 **오른쪽에서 왼쪽 방향으로 일정한 속도로 천천히 계속 이동**
- 일반적인 한 장씩 넘어가는 carousel 방식이 아니라, 여러 카드가 끊김 없이 계속 흘러가는 **marquee 형태의 infinite slider**로 구현
- 마지막 상품 다음에 첫 번째 상품이 자연스럽게 연결되도록 상품 목록을 복제하여 **seamless infinite loop** 구현
- 루프가 다시 시작되는 순간 점프하거나 끊기는 현상이 없어야 함
- 애니메이션 easing은 `linear`
- 기본 이동 속도는 느리고 여유롭게 설정
- 권장 기준: **카드 1장 너비인 300px를 이동하는 데 약 4\~5초**
- 전체 상품 개수에 맞춰 약 `30~45초 linear infinite` 범위에서 자연스럽게 조정
- 사용자가 직접 좌우로 드래그 또는 스와이프할 수 있도록 구현
- 필요할 경우 좌우 화살표 버튼으로도 이동 가능하게 구현
-상품 카드의 이미지 자동 슬라이드
(img/상품) 폴더의 상품 이미지를 사용한다.
각 상품마다 이미지가 여러 장 존재하며, 해당 상품에 속하는 이미지들을 하나의 이미지 그룹으로 묶어서 사용한다.
서로 다른 상품의 이미지를 섞지 않는다.
상품 카드 안에서 해당 상품의 여러 이미지가 2초마다 자동으로 다음 이미지로 변경되도록 구현한다.
ex):설화먹비 이미지1 → 설화먹비 이미지2 → 설화먹비 이미지3 → 설화먹비 이미지1 → 반복
이미지 전환 간격: 2초
마지막 이미지 다음에는 다시 첫 번째 이미지로 돌아가는 무한 반복
카드 자체가 바뀌는 것이 아니라 카드 내부 상품 이미지만 변경
상품명, 설명, 별점, 가격, 재고수량 등 상품 정보는 그대로 유지
이미지가 바뀌어도 카드의 크기와 레이아웃이 움직이지 않아야 함
모든 이미지는 동일한 이미지 영역 안에서 표시
width: 100%
height: 100%
object-fit: contain
이미지 전환 효과
이미지가 갑자기 깜빡이는 느낌이 들지 않도록 아주 짧은 fade 효과를 적용한다.
권장:opacity transition: 0.25s ~ 0.4s ease
단, 이미지가 바뀔 때 빈 화면이나 흰색 화면이 순간적으로 나타나지 않도록 한다.
다음 이미지는 미리 로드(preload)하여 전환 시 끊김이 없게 구현한다.
상품별 이미지 매칭
상품 데이터에 이미지 배열을 만들어 관리한다.
개념적으로 다음과 같이 구성한다.
설화먹비 → [이미지1, 이미지2, 이미지3, 이미지4]
자운설화 → [이미지1, 이미지2, 이미지3]
청화월영 → [이미지1, 이미지2, 이미지3, 이미지4]
각 상품마다 이미지 개수가 서로 달라도 정상적으로 작동해야 한다.
상품 카드가 변경되면:
기존 상품 이미지 자동재생 타이머를 제거한다.
새로 선택한 상품의 첫 번째 이미지를 즉시 표시한다.
해당 상품의 이미지 배열을 기준으로 새로운 2초 자동재생을 시작한다.
다른 상품의 이미지가 순간적으로 나타나지 않도록 한다.

#### 프로그레스 표시
띠배너 아래에 얇은 프로그레스바 스타일의 navigation을 배치한다.
단, 일반 슬라이더처럼 현재 슬라이드 번호를 표시하는 방식이 아니라\
**자동 슬라이더가 움직이고 있다는 것을 시각적으로 보여주는 보조 UI**로 사용한다.
디자인은 최대한 얇고 심플하게 구성한다.

### Mouse Over
상품 이미지에 마우스를 올리면:
1. **전체 자동 슬라이더를 즉시 일시정지한다.**
2. 현재 카드의 메인 이미지를 해당 상품의 **착용 전 상품 단독 이미지**로 딜레이 없이 즉시 교체한다.
3. fade transition 없이 즉시 변경하거나 최대 `0.15s` 이내의 아주 짧은 transition만 사용한다.
4. 카드의 상품정보와 장바구니 버튼을 표시한다.

Mouse Out 시:
- 상품 이미지를 기존 착용 이미지로 복원
- 자동 슬라이더를 현재 위치에서 다시 자연스럽게 재생
- 처음 위치로 돌아가지 말 것

### 카드 내부 상품 정보
MouseOver시 각 카드에는 다음 정보를 표시한다.
- 해당 상품 이미지 (img/상품 폴더 정면.png)
- 상품명 (20px) / Black / 명확하게 강조
- 상품 간단 설명 (15px) / Gray(#777777)
 - 별점
  - ex): `★★★☆ 4.8`
-  가격
  - 다른 정보보다 굵고 크게 강조
- 사이즈 및 사이즈별 현재 재고수량
ex):
`[ S · 품절 ] [ M · 2개 ] [ L · 4개 ]`
재고 상태에 따라 스타일을 구분한다.
- 품절 → Gray 처리
- 재고 있음 → 기본 Black
- 재고가 얼마 남지 않았을 경우 필요하면 강조 표시

### 장바구니
각 카드 오른쪽 상단에 장바구니 아이콘을 absolute position으로 배치한다.
- 위치: 카드 오른쪽 위
- 아이콘 컬러: `RED`
- 상품 이미지 위에 표시
- 카드 전체 클릭 이벤트와 장바구니 아이콘 클릭 이벤트를 분리한다.
장바구니 아이콘 클릭 시:
`✓ 장바구니에 추가되었습니다.`
Toast 메시지를 표시한다.
Toast는 약 2초 후 자연스럽게 사라지게 한다.
**장바구니 아이콘 클릭 시 상세페이지가 열리지 않도록 이벤트 버블링을 방지한다.**

### 카드 클릭
장바구니 버튼을 제외한 상품 카드 영역을 클릭하면 해당 상품의 상세페이지로 이동한다.
- 카드 전체에 `cursor: pointer`
- 상품마다 연결된 상세페이지 URL을 사용
- 장바구니 버튼 클릭은 상세페이지 이동에서 제외

### 애니메이션 중요 조건
- 오른쪽 → 왼쪽 방향으로만 자동 이동
- 자동 이동 중 속도가 빨라지거나 느려지지 않게 `linear` 적용
- 무한루프 연결부에서 끊김이 없어야 함
- 마지막 카드 뒤에 첫 카드가 바로 연결되어야 함
- hover 시 해당 카드만 멈추는 것이 아니라 **띠배너 전체 이동을 멈춤**
- mouseout 시 기존 위치에서 그대로 다시 이동
- hover 때문에 레이아웃의 높이 또는 카드 크기가 변경되지 않도록 할 것
- 이미지 교체 시 카드 크기 및 위치가 흔들리지 않도록 `object-fit: cover` 적용
- 데스크톱에서는 hover, 모바일에서는 터치/스와이프 중심으로 동작
- `prefers-reduced-motion` 환경에서는 자동 애니메이션을 최소화한다.

# =========================
# Supabase 데이터베이스
# =========================

연화재실은 **개량한복, 액세서리, 굿즈를 판매하는 쇼핑몰**이다.

이 사이트는 대여 사이트가 아니다.

따라서 DB에 다음 개념을 만들지 않는다.

- 대여기간
- 대여 시작일
- 대여 종료일
- 반납일
- 대여 예약
- 날짜별 대여 예약
- 대여중
- 반납예정
- 반납완료

상품은 일반 쇼핑몰처럼:

`상품 선택 → 사이즈 선택 → 수량 선택 → 장바구니 → 주문 → 재고 차감 → 배송 → 구매확정 → 후기`

구조로 구현한다.

현재 프로젝트는 Supabase와 연결되어 있으므로 회원, 상품, 재고, 장바구니, 주문, 후기, 관리자 데이터는 localStorage가 아닌 **Supabase Database**를 기본 데이터 저장소로 사용한다.

UI ON/OFF 등 단순한 브라우저 환경설정만 localStorage를 사용할 수 있다.

- 주문

# 2. 회원

회원 인증정보와 비밀번호는 별도 public 테이블에 저장하지 않는다.

Supabase Auth의:

`auth.users`

를 사용한다.

회원가입:

`supabase.auth.signUp()`

로그인:

`supabase.auth.signInWithPassword()`

로그아웃:

`supabase.auth.signOut()`

로그인 상태:

`supabase.auth.getSession()`

`supabase.auth.onAuthStateChange()`

를 이용한다.

# 4. 관리자 권한

관리자 테스트 이메일:

`heechic@naver.com`

해당 Supabase Auth 사용자의 profiles 데이터를:

`role = 'admin'`

으로 설정한다.

단, 최종 관리자 권한은 이메일 문자열을 프론트에서 단순 비교해서 판단하지 않는다.

구조:

`Supabase Auth → auth.uid() → profiles.id → profiles.role`

`profiles.role = 'admin'`

인 경우에만 관리자 권한을 부여한다.

일반 사용자가 자신의 role을 admin으로 변경할 수 없도록 RLS를 적용한다.

# 14. 재고 처리

연화재실은 판매 사이트이다.

재고는 날짜별 예약재고가 아니라:

`product_variants.stock_quantity`

를 사용한다.

주문 확정 시:

`현재 재고 - 구매 수량`

으로 차감한다.

주문 취소/반품으로 재고복원이 필요한 경우 안전하게 다시 증가시킨다.

일반 사용자가 브라우저에서 직접 stock_quantity를 UPDATE할 수 없도록 RLS를 적용한다.

# 31. 안전한 주문 RPC

주문과 재고차감은 프론트에서 각각 따로 INSERT/UPDATE하지 않는다.

가능하면 PostgreSQL Function/RPC:

`create_order()`

를 만든다.

처리:

```text
1. 로그인 사용자 확인
2. 장바구니 조회
3. DB에서 현재 상품 가격 다시 조회
4. DB에서 현재 재고 다시 확인
5. 할인/쿠폰 계산
6. 배송비 계산
7. orders 생성
8. order_items 생성
9. 추가구성 저장
10. product_variants.stock_quantity 차감
11. inventory_movements 기록
12. 장바구니 비우기
13. 성공 시 commit
14. 실패하면 전체 rollback
```

클라이언트가 보내온 가격을 그대로 신뢰하지 않는다.

# 32. 초과판매 방지

예:

```text
S 사이즈 재고 = 1

사용자 A → 1개 주문
사용자 B → 1개 주문
```

둘 다 성공하면 안 된다.

주문 transaction 내부에서 재고를 검증하고 안전하게 차감한다.

재고가 부족하면:

`선택하신 상품의 재고가 변경되었습니다.`

안내 후 주문을 중단한다.

로 변경하면 사용자 상품카드와 상세페이지에서도 최신 재고를 가져오도록 한다.

# 73. 이미지 저장방식

기존 로컬 파일:

`/img/...`

은 경로를 DB에 저장할 수 있다.

관리자가 새 이미지를 업로드하면 Supabase Storage 사용.

추천 bucket:

- product-images
- review-images
- site-media

DB에 이미지 바이너리를 직접 저장하지 않는다.

# 78. Migration 관리

Supabase 테이블은 가능하면 migration SQL로 관리한다.

폴더:

`supabase/migrations/`

기존 migration을 삭제하거나 덮어쓰지 않는다.

새 migration을 추가한다.

필요한 항목:

- CREATE TABLE
- FOREIGN KEY
- UNIQUE
- CHECK
- INDEX
- RLS
- POLICY
- FUNCTION
- TRIGGER
- VIEW

# 79. 관리자 페이지와 DB 연동

관리자 페이지에서 수정한 정보는 실제 Supabase를 UPDATE하고 사용자 사이트에서 같은 DB를 조회한다.

예:

```text
관리자 페이지

달빛하얀소복
판매가격 89,000원
↓
99,000원

Supabase products.sale_price
↓
99,000원

메인 상품카드
상세페이지
검색
장바구니
챗봇
관리자 상품관리

전부 99,000원 표시
```

상품 정보를 여러 JS 파일에 중복으로 하드코딩하지 않는다.

# 80. 관리자 대시보드 계산

별도 대시보드 테이블 생성 금지.

DB를 집계한다.

```text
전체상품
→ products COUNT

판매중
→ products.status = public

품절
→ 모든 활성 variant의 stock_quantity = 0

재고부족
→ stock_quantity <= low_stock_threshold

오늘 주문
→ orders.ordered_at = 오늘

오늘 결제완료
→ payment_status = paid

오늘 출고
→ shipments.shipped_at = 오늘

배송중
→ shipments.status = shipping

배송완료
→ shipments.status = delivered

오늘 매출
→ 오늘 paid 주문 SUM(total_amount)

이번달 매출
→ 현재 월 paid 주문 SUM(total_amount)

미답변 문의
→ inquiries.status = pending

미답변 후기
→ 관리자 답변 없는 reviews
```

현재 schema와 migration을 먼저 확인한 뒤 기존 데이터를 보존하면서 필요한 migration만 추가한다.

실제 프로젝트에서 확인되지 않은 이미지 파일, 상품 가격, 재고수량 등의 값은 임의로 사실처럼 만들지 않는다.
